# Source Code vs Byte Code vs Binary Code

**Example file:** `01_HellowWorld.js`
**Source content:** `console.log("Hello the testing Academy");`

---

## Comparison Table

| Aspect | **Source Code** | **Byte Code** | **Binary Code (Machine Code)** |
|---|---|---|---|
| **Definition** | Human-readable instructions written in a programming language | Intermediate representation between source code and machine code | CPU-executable instructions (0s and 1s) |
| **Example** | `console.log("Hello the testing Academy");` | `0x2a, 0x3e, 0x01, ...` (IL instructions) | `10101010 00111100 00000001 ...` |
| **Readability** | Readable by humans | Difficult for humans to read | Mostly unreadable by humans |
| **Who executes it** | Developers write and read it | Virtual Machine (e.g., V8, JVM, CLR) | CPU hardware directly |
| **File extension** | `.js`, `.py`, `.java`, `.c`, `.cpp` | `.class` (Java), `.pyc` (Python), V8 Ignition bytecode (no file) | `.exe`, `.dll`, `.o`, `.out`, no extension (Linux ELF) |
| **Performance** | Slowest (must be interpreted/compiled first) | Faster than source, slower than binary | Fastest (native to the CPU) |
| **Portability** | Runs anywhere with the language runtime | Portable across platforms with corresponding VM | **Not portable** — tied to specific CPU architecture (x86, ARM, etc.) |
| **Generation step** | — You write this manually | Step 1: Source → Compiler → Byte Code | Step 2: Byte Code → JIT/AOT Compiler → Binary Code |
| **How it applies to `01_HellowWorld.js`** | This **is** the source code file you created | When Node.js runs this file, the V8 engine compiles it to **Ignition bytecode** internally | V8's **TurboFan** JIT compiler further compiles hot bytecode into native machine code for the CPU |
| **Analogy** | A **recipe** written in English | The recipe translated into **kitchen shorthand** that a chef-in-training can follow | The **final cooked dish** — ready to eat, no further work needed |

## How the Example Flows Through These Stages

```
01_HellowWorld.js (Source Code)
        │
        ▼
   Node.js starts
        │
        ▼
   V8 Parser ──► AST (Abstract Syntax Tree)
        │
        ▼
   V8 Ignition ──► Byte Code (intermediate)
        │
        ▼
   V8 TurboFan (JIT) ──► Binary/Machine Code
        │
        ▼
   CPU executes the binary instructions
        │
        ▼
   Output: "Hello the testing Academy"
```

## Key Takeaways

1. **You only write source code.** Byte code and binary code are generated automatically by the runtime/compiler.
2. **JavaScript never truly runs as source.** It's always compiled to byte code (and then to machine code) by V8 before execution.
3. **Binary code is platform-specific.** The machine code generated by V8 on your Windows x64 laptop and Docker Ubuntu on ARM will be completely different, even though they ran the same source file.
4. **Byte code is the bridge.** It gives a balance of portability (source code ideal) and performance (binary code ideal).
